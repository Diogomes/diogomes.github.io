Navegação em apps: stack, tabs e deep links

Diogo Gomes  ·  22 de Junho, 2026Jun 22, 2026  ·  3 min de leitura3 min read

Navegar em um app é mais do que trocar de tela: é gerenciar um histórico de onde o usuário esteve, garantir que o botão voltar faça o esperado e permitir que uma URL abra direto numa tela específica. Esses padrões — pilha, abas, modais e deep links — são universais entre iOS, Android, React Native e Flutter, e entender como se encaixam evita os bugs de navegação mais comuns.

A pilha de navegação (push/pop)

A metáfora é uma pilha de pratos. Cada tela nova que você abre é um prato colocado por cima (push); voltar é tirar o prato de cima (pop), revelando o anterior. A tela visível é sempre o topo da pilha.

topo -> [ Detalhe do produto ]   (push)
        [ Lista de produtos ]
        [ Home ]              <- base

// usuário aperta "voltar":
topo -> [ Lista de produtos ]   (pop)
        [ Home ]

O botão voltar (e por que o Android é diferente)

No iOS o "voltar" mora dentro da própria tela (canto superior esquerdo). No Android existe um botão/gesto voltar do sistema, fora do seu controle visual, e o usuário o usa o tempo todo. Você precisa garantir que ele faça pop da pilha de forma coerente — e tratar o caso de estar na raiz (onde voltar pode fechar o app). Ignorar isso gera o clássico bug de "voltar fecha o app no meio do fluxo" ou "voltar não sai do modal".

Abas (tab bar)

As abas dividem o app em seções paralelas — cada aba costuma ter sua própria pilha independente. Trocar de aba não apaga o histórico da anterior: ao voltar para ela, o usuário reencontra a tela onde estava. Pense em várias pilhas de pratos lado a lado, e a tab bar escolhendo qual está ativa.

Navegação modal

Um modal interrompe o fluxo para uma tarefa pontual — login, um formulário, uma confirmação — geralmente deslizando de baixo para cima. Diferente do push (que avança no mesmo fluxo), o modal se sobrepõe e é dispensado (dismiss), não "popado". Misturar os dois conceitos é erro comum.

PadrãoQuando usarSair com
Push (stack)Aprofundar no mesmo fluxo (lista → detalhe)Voltar / pop
TabsSeções paralelas do appTrocar de aba
ModalTarefa pontual que interrompeFechar / dismiss

Deep links e universal/app links

Um deep link é uma URL que abre uma tela específica em vez da home — por exemplo, tocar em meuapp://produto/42 e cair direto no produto 42. Os universal links (Apple) e app links (Android) vão além: usam uma URL https normal do seu site que, se o app estiver instalado, abre o app na tela certa; senão, abre o navegador. Isso exige verificar a posse do domínio (um arquivo de associação no servidor).

https://loja.com/produto/42
   |
   +-- app instalado? --> abre app na tela do produto 42
   |
   +-- senão -----------> abre no navegador

É comum em entrevista pedir para descrever o que acontece desde tocar num link até a tela abrir, incluindo o caso "app não instalado". No dia a dia isso aparece em campanhas de marketing, notificações e compartilhamento.

Estado e navegação andam juntos

Quando um deep link abre uma tela no meio do fluxo, você precisa montar uma pilha coerente por baixo (para o voltar funcionar) e considerar que o app pode ter sido iniciado do zero — exatamente os cenários do ciclo de vida do app. Restaurar a navegação após o app ser morto pelo SO é um caso que une os dois temas.

Navegação é gestão de histórico, não só de telas. Se você sempre souber qual é a pilha atual e o que o "voltar" deveria fazer, a maioria dos bugs de navegação some.

Conclusão

Pilha (push/pop), abas com históricos paralelos, modais que se sobrepõem e deep links que entram pela URL formam o vocabulário de navegação que você usa em qualquer plataforma. Dominar o comportamento do botão voltar e o fluxo dos universal links separa quem entrega telas de quem entrega experiências consistentes.

Navigating in an app is more than switching screens: it is managing a history of where the user has been, making sure the back button does what's expected, and letting a URL open straight onto a specific screen. These patterns — stack, tabs, modals and deep links — are universal across iOS, Android, React Native and Flutter, and understanding how they fit together prevents the most common navigation bugs.

The navigation stack (push/pop)

The metaphor is a stack of plates. Each new screen you open is a plate placed on top (push); going back is removing the top plate (pop), revealing the previous one. The visible screen is always the top of the stack.

top -> [ Product detail ]   (push)
        [ Product list ]
        [ Home ]            <- base

// user presses "back":
top -> [ Product list ]     (pop)
        [ Home ]

The back button (and why Android is different)

On iOS, "back" lives inside the screen itself (top-left corner). On Android there is a system back button/gesture, outside your visual control, and users press it all the time. You need to make sure it pops the stack coherently — and handle the case of being at the root (where going back may close the app). Ignoring this produces the classic bug of "back closes the app in the middle of a flow" or "back doesn't dismiss the modal".

Tabs (tab bar)

Tabs split the app into parallel sections — each tab usually has its own independent stack. Switching tabs doesn't erase the previous one's history: when the user returns, they find the screen they were on. Think of several stacks of plates side by side, with the tab bar choosing which one is active.

Modal navigation

A modal interrupts the flow for a one-off task — login, a form, a confirmation — usually sliding up from the bottom. Unlike push (which moves forward within the same flow), a modal overlays the screen and is dismissed, not "popped". Mixing the two concepts is a common mistake.

PatternWhen to useExit with
Push (stack)Drilling deeper in the same flow (list → detail)Back / pop
TabsParallel sections of the appSwitch tabs
ModalOne-off task that interruptsClose / dismiss

Deep links and universal/app links

A deep link is a URL that opens a specific screen instead of home — for example, tapping meuapp://produto/42 and landing directly on product 42. Universal links (Apple) and app links (Android) go further: they use a normal https URL from your website that, if the app is installed, opens the app on the right screen; otherwise, it opens the browser. This requires verifying domain ownership (an association file on the server).

https://loja.com/produto/42
   |
   +-- app installed? --> opens app on product 42 screen
   |
   +-- otherwise -------> opens in the browser

Interviewers often ask you to describe what happens from tapping a link to the screen opening, including the "app not installed" case. Day to day, this shows up in marketing campaigns, notifications and sharing.

State and navigation go together

When a deep link opens a screen in the middle of a flow, you need to build a coherent stack underneath (so back works) and consider that the app may have been started from scratch — exactly the scenarios from the app lifecycle. Restoring navigation after the app was killed by the OS is a case that ties both topics together.

Navigation is history management, not just screen management. If you always know what the current stack is and what "back" should do, most navigation bugs disappear.

Conclusion

Stacks (push/pop), tabs with parallel histories, modals that overlay and deep links that come in through a URL make up the navigation vocabulary you use on any platform. Mastering the back button's behavior and the flow of universal links separates those who deliver screens from those who deliver consistent experiences.
